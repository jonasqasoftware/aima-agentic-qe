COMO USAR · GUIA CANÔNICO

Como usar o AIMA.

Este é o guia único de onboarding do método. As demais páginas do site linkam para cá em vez de repetir este conteúdo.

AIMA EM 5 MINUTOS

Quatro perguntas, nessa ordem.

A · ANÁLISE

Qual problema estamos tentando resolver?

I · IMPACTO

O que vamos mudar?

M · METRIFICAÇÃO

Como saberemos se melhorou?

A · APRESENTAÇÃO

O que os resultados nos dizem?

Não é preciso escolher um framework, consultar o léxico ou entender a arquitetura interna do AIMA para começar. Essas respostas já são o suficiente para aplicar o método uma primeira vez.

AIMA CANVAS

A ferramenta prática do método.

O Canvas organiza as mesmas quatro etapas em um formulário único, preenchível no navegador, com exportação em Markdown.

Abrir o AIMA Canvas
PASSO A PASSO · OPCIONAL

Quatro ferramentas, uma por etapa.

Cada uma aprofunda uma etapa do AIMA Canvas. São opcionais — o método funciona sem elas.

A

Analysis Canvas

Aprofunda a Análise: contexto, problema, riscos e o que ainda não se sabe.

I

Impact Map

Aprofunda o Impacto: onde agir primeiro e qual mudança testar.

M

Evidence Card

Aprofunda a Metrificação: qual evidência e métrica vão mostrar o resultado.

A

Decision Brief

Aprofunda a Apresentação: resultado, aprendizado e decisão registrada.

Quer ainda mais profundidade? Os 20 frameworks avançados em Labs cobrem casos específicos de cada etapa.

UM EXEMPLO PRÁTICO

As quatro perguntas, respondidas.

A · ANÁLISE

A API está apresentando aumento de erros 500.

I · IMPACTO

Priorizar o fluxo de pagamento, o de maior exposição a esse erro.

M · METRIFICAÇÃO

Erro 500, latência e taxa de sucesso das chamadas.

A · APRESENTAÇÃO

Decidir se a correção pode ir para produção com base nesses sinais.
